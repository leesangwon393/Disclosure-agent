A-7·A-8  agent/derived_facts.py
  합계·평균·차이·건수·순위를 파이썬이 계산해 ▶▶ 로 못 박는다.
  calculation.py(증감률·비율·CAGR)를 ask_v2 경로에 연결했다 —
  "계산은 LLM 에 맡기지 않는다"고 적혀 있는데 옛 agent_loop 에만
  물려 있어 지금 파이프라인이 한 번도 부르지 않고 있었다.
  실측 근거: 계산이 붙는 최대/최소 96%, 합계 50%, 비율 40%, 평균 0%.

  같이 잡은 것 둘
  - "연평균성장률" 질문에 증감률과 CAGR 이 둘 다 나갔다. "성장률" 이 두
    목록에 다 걸린 탓. CAGR 을 물으면 CAGR 만 답한다.
  - "비율" 을 같은 항목의 올해/작년으로 계산하고 있었다. 그건 비중이
    아니라 증감률이다. 두 항목이 모두 질문에 적혀 있을 때만 계산하고,
    회사·시점·단위가 다르면 계산하지 않는다.

A-9  scripts/score_answers.py
  a) evidence_hit 을 정정 체인(correction_group_id)으로 판정한다.
     정답지에 원본 ID 가 박혀 있는데 검색이 최신 정정본을 가져오면
     검색실패로 찍혔다 — 43건 중 14건이 그것이었다. 재채점 경로도 같이.
  b) 단위 환산을 인정한다. 0.0430 = 4.30% (% 가 붙은 수만 100배로 본다),
     3,112,850 = 3조 1,128억원.
  c) unit_stated — 단위를 적었는가를 별도 지표로 센다. 대회는 사람이
     채점하는데 지금은 숫자만 비교해 단위 누락이 안 보였다.

  테스트 하나를 고쳤다. test_rescaled_number_is_not_a_hit 이
  "7,661,584백만원 은 7,661,584,000,000 의 정답이 아니다" 라고 못 박고
  있었는데 두 값은 같다. 맞는 답을 오답으로 세던 규칙이다.
